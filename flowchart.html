WuWa Calculator

A React + Zustand app that simulates Wuthering Waves team rotations. Character, weapon and echo mechanics are data (JSON with a small DSL) fetched from a separate data repo; a Web Worker runs the simulation; everything a user builds persists to localStorage. Each section below is one area of the codebase.

UI component / hook Zustand store Logic (pure simulation, math) Worker thread Data / storage / external Stale / error path

Architecture layers

every folder in src/

Pages call stores; stores call the worker client and the data layer; the worker runs the pure logic. A few components (the rotation row, the Builder's autocomplete) also read logic directly to build their dropdowns.

Live recalculation and the worker

useRotationStore.runWorkerCalc, calcWorkerClient, calc.worker

Editing rows never runs damage. It sends a cheap recalculate: times, gauges, loop info, errors. The worker has its own DataLoader, and requests run one at a time.

Inside recalculateState

logic/TimelineEngine.ts

One pass over the rows in order. Each row inherits the previous row's state (resource pools, buffs, trackers, cooldowns), works out how long to wait and how long the move takes, validates it, then runs the mechanics that its events trigger.

Events, effects and the DSL at run time

A mechanic node's triggerRule is a tiny language: OnCast(...) IF condition (or ALWAYS). It is compiled once into a function, registered under its event, and evaluated against a context built from the current row.

Data, freshness, persistence and deployment
